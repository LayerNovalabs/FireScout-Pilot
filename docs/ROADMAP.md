# FireScout Roadmap

## Phase 1 — Competition Foundation

Goal: Build a stable and self-guided competition version that judges can operate without assistance.

Main objectives:

- Project architecture
- Simulator-first device model
- Mission selection
- Simulated assets
- Live telemetry
- Interactive operational map
- Operational events
- Decision recommendations
- Mission summary
- Basic report generation

## Phase 2 — Competition Experience

Goal: Make the platform intuitive, visually convincing, and easy to explore.

Main objectives:

- Guided mission launch
- Auto Demo mode
- Manual event controls
- Mission-specific interfaces
- Wildfire scenario
- Flood scenario
- Maritime SAR scenario
- Mission timeline
- Mission replay
- System health indicators

## Phase 3 — Core Product Hardening

Goal: Convert the competition version into a stronger product foundation.

Main objectives:

- Persistent database
- User accounts
- Permissions
- Audit logs
- Configuration management
- Improved testing
- API documentation
- Deployment configuration
- Security review

## Phase 4 — Real Device Integrations

Goal: Connect real operational systems through adapters.

Possible integrations:

- MAVLink-compatible vehicles
- Pixhawk-based systems
- DJI-supported integration paths
- Ground robots
- Maritime vehicles
- IoT sensors
- Weather stations

## Phase 5 — Intelligence Expansion

Goal: Add real data processing and AI capabilities.

Possible modules:

- Fire detection
- Smoke detection
- Victim detection
- Object detection
- Risk analysis
- Route recommendation
- Search-area optimization
- Drift estimation
- Decision support

## Phase 6 — Commercial Deployment

Goal: Prepare FireScout for pilots with real organizations.

Main objectives:

- Cloud deployment
- Edge deployment
- Multi-organization support
- Fleet management
- Training environment
- Mission analytics
- Operational reporting
- Integration SDK
- Pilot deployments

## Development Principle

The competition version must not be treated as disposable code.

Each phase should extend the same core architecture whenever practical.
